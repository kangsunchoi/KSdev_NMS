# 02. 구성, 배포, 운영

## 1. 전체 구조

```
[실장비 / 시뮬]          [Node-RED :1880]            [NetVision 백엔드 :8001]        [대시보드 :8080]
스위치, PLC  --ping/SNMP/Modbus-->  수집 플로우  --HTTP POST-->  /api/ingest 등  --WebSocket-->  화면
                                       ^                              |
                                       +---- GET /api/devices, /api/discovery (수집 대상/설정 조회)
```

- 역할 분리: Node-RED는 수집(감각기관), 백엔드는 저장과 판정, 프론트는 시각화
- 백엔드 변경은 프론트 수정 없이 기존 화면이 새 데이터를 그대로 소비하도록 설계

## 4. 백엔드 설정 (`backend/.env`)

실제 파일은 VM에만 있고 저장소에는 `backend/.env.example`만 있습니다.

기본 항목:

```
MONGO_URL="mongodb://localhost:27017"
DB_NAME="netvision"
CORS_ORIGINS="http://192.168.108.129:8080"
SIMULATION_MODE=false
```

- `SIMULATION_MODE`: `true`는 목업 20대 자동 시드 + 랜덤 시뮬, `false`는 실데이터 모드

추가 토글 (전부 기본값으로 두면 기존 동작과 동일):

| 항목 | 기본 | 설명 |
|---|---|---|
| `AUTH_ENABLED` | false | 로그인 + RBAC |
| `AUTH_SECRET` | (빈 값) | 인증을 켤 때 필수. 비우면 재시작마다 로그인 풀림 |
| `ADMIN_USER` / `ADMIN_PASSWORD` | admin / (예시값) | 인증 ON이고 사용자가 0명일 때 최초 관리자 생성 |
| `AUTH_TOKEN_TTL_HOURS` | 12 | 로그인 토큰 유효시간 |
| `INGEST_TOKEN` | (빈 값) | 값을 넣으면 수집 API가 `X-Ingest-Token` 헤더 요구 |
| `AUDIT_ENABLED` | true | 변경 요청 감사 로그 (30일 TTL) |
| `AUDIT_TTL_DAYS` | 30 | 감사 로그 보관일 |
| `RCA_ENABLED` | true | 알람에 상위 장애 연관(`correlated_to`) 주석만 추가 |
| `SLACK_WEBHOOK_URL` | (빈 값) | 값이 있으면 Slack 통지 |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | (빈 값) | 둘 다 있으면 Telegram 통지 |
| `NOTIFY_MIN_SEVERITY` | critical | 통지 최소 심각도 (info, warning, critical) |
| `UNMANAGED_MIN_MACS` | 2 | 미관리 세그먼트 판정 기준 MAC 개수 (`.env.example`에는 없음, 코드 기본값) |

`AUTH_SECRET` 생성 (VM):

```bash
python3 -c "import secrets;print(secrets.token_hex(32))"
```

## 6. systemd와 Nginx

유닛 파일과 Nginx 설정 원문은 대화 기록에 남아 있지 않습니다 [미확인]. VM에서 아래로 확인해서 이 문서에 붙여두는 것을 권장합니다.

```bash
# (VM)
systemctl cat netvision-backend
systemctl cat nodered
ls /etc/nginx/sites-enabled/
sudo nginx -T 2>/dev/null | grep -n "8080" -A30
```

Nginx 필수 조건:

- `/api/` 프록시에 WebSocket 업그레이드 헤더가 있어야 합니다. 이 앱은 폴링 대체가 없어서 없으면 화면이 자동 갱신되지 않습니다.

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8001;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
}
```

- 위 블록은 필수 요소를 보여주는 참고용입니다. 실제 파일과 대조하세요.

## 8. Node-RED 수집기

### 8.1 설치 이력

```bash
# (VM) Node-RED 본체는 공식 설치 스크립트 사용
sudo ufw allow 1880/tcp

# 팔레트 노드
cd ~/.node-red
npm install node-red-node-ping node-red-node-snmp node-red-contrib-modbus
sudo systemctl restart nodered

# 디스커버리용 fping (non-root ping 권한 포함)
sudo apt-get install -y fping
sudo setcap cap_net_raw+ep $(which fping)

# SNMP CLI (CDP, 인터페이스 플로우가 exec로 사용)
sudo apt-get install -y snmp

# 장비 없이 SNMP 테스트할 때: VM 자신을 SNMP 장비로
sudo apt-get install -y snmpd
```

- 초기 설정: 사용자 보안 Yes(관리자 계정, full access), Projects 기능 No
- 편집 화면 비밀번호는 문서에 남기지 않습니다

### 8.2 플로우 목록

모든 플로우는 `127.0.0.1:8001`로 POST합니다. 플로우는 현재 VM의 `~/.node-red/flows.json`에만 있고 저장소에 없습니다.

| 파일 | 탭 | 역할 | 실행 | 상태 |
|---|---|---|---|---|
| `netvision_collector_flow.json` | NetVision Collector | 등록 장비 ping → `/api/ingest` | 30초 | 완료 [확인] |
| `netvision_discovery_flow.json` | NetVision Discovery | fping 스윕 → `/api/devices` (구버전) | 수동 | discovery2로 대체, 비활성화 필요 |
| `netvision_discovery2_flow.json` | NetVision Discovery2 | `/api/discovery`의 `run_requested` 폴링 → fping → `/api/discovery/register` | 1분 폴링 | 완료 [확인] |
| `netvision_identify_flow.json` | NetVision Identify | sysObjectID/sysDescr로 vendor/type 분류 → PATCH | 수동 | 완료 (snmpd 자가 테스트) |
| `netvision_snmp_flow.json` | NetVision SNMP | 스위치 CPU 폴링 → `/api/ingest` | 60초 | 구조 완료, 모델별 OID 미확정 |
| `netvision_lldp_flow.json` | NetVision LLDP | `lldpRemSysName` walk → `/api/links` | 수동 | 스캐폴드 |
| `netvision_cdp_flow.json` | NetVision CDP | `cdpCacheTable` walk → `/api/links` | 수동 | 스캐폴드 |
| `netvision_modbus_flow.json` | NetVision Modbus | Modbus 시뮬 서버 + 수집 → `/api/metrics` | 5초 | 시뮬로 전 구간 검증 |
| `netvision_interfaces_flow.json` | NetVision Interfaces | `ifTable` walk → `/api/interfaces` | 30초 | 최종본(ifTable 단일) Deploy 미확인 |

주의:

- 구 디스커버리와 discovery2가 동시에 돌면 중복 등록 시도가 생깁니다. 구버전 탭은 Disable
- 인터페이스 플로우는 기존 탭을 삭제한 뒤 최종본을 Import → Deploy
- 수집 대상: `device_type=switch` + `protocol=snmp`. SNMP community는 디스커버리 설정값(전역)을 사용

### 8.3 플로우 Import

1. `http://192.168.108.129:1880` 접속, 로그인
2. 우측 상단 메뉴 → Import → 파일 선택 → Import
3. Deploy

## 9. 시뮬 ↔ 실데이터 전환

순서가 중요합니다. 시뮬을 먼저 끄고 초기화해야 목업이 다시 생기지 않습니다.

```bash
# (VM) 1. backend/.env 에서 SIMULATION_MODE=false 로 수정
nano ~/KSdev_NMS/backend/.env

# 2. 재시작
sudo systemctl restart netvision-backend

# 3. 시뮬 꺼졌는지 확인 (false 여야 함)
curl -s http://127.0.0.1:8001/api/sim/mode; echo

# 4. 전체 초기화 (디스커버리로 등록한 장비도 지워짐)
curl -s -X POST http://127.0.0.1:8001/api/mock/reset; echo
```

- 일부 목업만 지울 때는 `mock/reset` 대신 정리 API를 씁니다 (미리보기 후 삭제):

```bash
# (VM) 미리보기
curl -s -X POST http://127.0.0.1:8001/api/devices/cleanup \
  -H 'Content-Type: application/json' \
  -d '{"name_prefixes":["SW-","PLC-","SNS-"],"ip_prefix":"10.20.","dry_run":true}' | python3 -m json.tool

# (VM) 실제 삭제
curl -s -X POST http://127.0.0.1:8001/api/devices/cleanup \
  -H 'Content-Type: application/json' \
  -d '{"name_prefixes":["SW-","PLC-","SNS-"],"ip_prefix":"10.20.","dry_run":false}' | python3 -m json.tool
```

- 재시작 없이 데모 보기: `POST /api/sim/mode {"enabled":true}` (재시작하면 `.env` 값으로 복귀)

## 10. 기능 켜기

1. 통지
   - `backend/.env`에 `SLACK_WEBHOOK_URL` 또는 `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` 입력 → restart
2. 수집 API 보호
   - `INGEST_TOKEN` 입력 → restart
   - 모든 Node-RED http request 노드에 `X-Ingest-Token` 헤더 추가 필요
3. 인증/RBAC
   - `AUTH_ENABLED=true`, `AUTH_SECRET`, `ADMIN_PASSWORD` 입력 → restart → 로그인 화면 표시
   - 켜기 전 주의: Node-RED가 호출하는 `GET /api/devices`, `GET /api/discovery`, `POST /api/fdb`, `POST /api/assets`는 수집 토큰 대상이 아니라서 인증 ON이면 401로 막힙니다 (코드 확인). `04_트러블슈팅.md` 참조

## 11. 검증 명령 모음

```bash
# (VM) 백엔드 상태와 시뮬 모드
systemctl is-active netvision-backend
curl -s http://127.0.0.1:8001/api/sim/mode; echo

# 장비 목록 (이름, IP, 타입)
curl -s http://127.0.0.1:8001/api/devices | python3 -c "import sys,json;d=json.load(sys.stdin);[print(x['name'],x['ip'],x['device_type']) for x in d]"

# 장비별 인터페이스 수집 현황
curl -s http://127.0.0.1:8001/api/devices | python3 -c "
import sys, json, urllib.request
for d in json.load(sys.stdin):
    try:
        r = json.load(urllib.request.urlopen('http://127.0.0.1:8001/api/devices/%s/interfaces' % d['id']))
        ifs = r.get('interfaces', [])
        print('%-16s %-8s ports=%-3s bps=%s' % (d['ip'], d.get('device_type'), len(ifs), any(i.get('in_bps') is not None for i in ifs)))
    except Exception:
        print('%-16s ports=err' % d['ip'])
"

# 링크 수동 테스트 (토폴로지에 선이 생기면 정상, 지우기는 POST /api/links/reset)
curl -s -X POST http://127.0.0.1:8001/api/links -H 'Content-Type: application/json' \
  -d '{"links":[{"source_ip":"192.168.108.2","neighbor_ip":"192.168.108.129","local_port":"Gi0/1","remote_port":"eth0"}]}'; echo

# 미관리 세그먼트 테스트 (등록된 스위치 IP의 한 포트에 MAC 3개 주입)
curl -s -X POST http://127.0.0.1:8001/api/fdb -H 'Content-Type: application/json' \
  -d '{"ip":"<스위치IP>","entries":[
    {"port":"Gi1/0/5","mac":"00:11:22:33:44:01"},
    {"port":"Gi1/0/5","mac":"00:11:22:33:44:02"},
    {"port":"Gi1/0/5","mac":"00:11:22:33:44:03"}]}'; echo

# 장비에서 직접 SNMP 확인
snmpbulkwalk -v2c -c public -On -t 5 -r 2 192.168.0.240 1.3.6.1.2.1.2.2.1 | head
```

- 화면 확인: Devices에서 장비 행의 차트 아이콘(지표), 네트워크 아이콘(인터페이스)
- bps는 두 번째 폴링부터 표시됩니다 (카운터 차이로 계산)
