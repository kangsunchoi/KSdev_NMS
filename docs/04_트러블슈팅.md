# 04. 트러블슈팅

실제로 겪었거나 코드 점검에서 찾은 문제입니다.

## 1. 배포 / 환경

| 증상 | 원인 | 해결 |
|---|---|---|
| 대시보드가 자동 갱신 안 됨 | Nginx `/api/` 프록시에 WebSocket 헤더 없음. 이 앱은 폴링 대체가 없음 | `proxy_http_version 1.1`, `Upgrade`, `Connection` 헤더 추가 (`02` 6절) |
| `pip install -r requirements.txt` 실패 | `emergentintegrations==0.2.0`이 PyPI에 없음, 미사용 패키지 다수 | 실제 import하는 최소 패키지만 설치 (`02` 5절) |
| 백엔드가 안 뜸 (포트 충돌) | ksdev 백엔드가 이미 8000 사용 | NetVision 백엔드는 8001, 별도 systemd, 별도 Nginx(8080) |
| ksdev와 데이터가 섞일 위험 | 같은 MongoDB 사용 | `DB_NAME="netvision"`으로 분리 |
| `:1880`에서 대시보드가 안 보임 / `:8080`에서 플로우가 안 보임 | 서로 다른 프로그램 | 1880은 Node-RED 편집, 8080은 대시보드 |
| `:1880` 접속 불가 | 서비스 미기동 또는 방화벽 | `systemctl is-active nodered`, `sudo ufw allow 1880/tcp` |
| 새 코드를 올렸는데 화면이 그대로 | push 누락, 빌드 미실행, 브라우저 캐시 | push 확인 → `yarn build` → Ctrl+Shift+R. 빌드 잔존 확인 명령은 `02` 7절 |
| OCI로 옮기면 수집이 안 됨 | OCI에서 사내망(192.168.0.0/24)으로 경로 없음(VPN 없음) | NMS는 내부 VM 유지 |

## 2. 목업 / 시뮬

| 증상 | 원인 | 해결 |
|---|---|---|
| 지워도 목업 20대가 다시 생김 | `SIMULATION_MODE=true` 상태에서 재시작이나 시뮬 루프가 다시 시드 | `.env`에서 false → restart → `sim/mode` 확인 → `mock/reset` 순서 |
| "Seed Mock" 누르면 실장비가 사라짐 | `mock/generate`가 `replace=True`로 기존 장비를 전부 지우고 생성 | 버튼 제거 완료(2026-06-06). API는 남아 있으니 직접 호출 금지 |
| `mock/reset` 후 디스커버리 장비도 사라짐 | reset은 전체 삭제 | 일부만 지울 땐 `/devices/cleanup` 미리보기 후 삭제, 끝나면 디스커버리 재실행 |

## 3. SNMP / 수집

| 증상 | 원인 | 해결 |
|---|---|---|
| 인터페이스가 0건 (백엔드, SNMP 둘 다 정상) | `snmpbulkwalk`에 서브트리를 여러 개 주면 첫 번째만 수집하고 나머지를 조용히 버림 | `ifTable`(`1.3.6.1.2.1.2.2.1`) 하나만 walk. 이름은 ifDescr(.2) 사용 |
| 10G 포트 속도가 이상함 | ifSpeed가 32비트 (약 4Gbps 상한) | 필요 시 ifHighSpeed / 64비트 카운터(ifXTable)로 전환. 단 위 다중 walk 문제 주의 |
| 고속 링크에서 bps가 가끔 빈칸 | 32비트 카운터 wrap → 음수 델타는 백엔드가 버림 | 실사용 영향 적음. 정밀하게는 64비트 카운터 |
| bps가 처음에 안 나옴 | 카운터 차이 계산이라 첫 샘플엔 값 없음 | 두 번째 폴링(30초 후)부터 표시 |
| 비스위치 장비에 "no interfaces parsed" 경고 | 디스커버리가 전부 `switch`로 등록해서 프린터/PC에도 수집 시도 | 정상. 식별 플로우로 타입 교정하거나 무시 |
| `node-red-node-snmp`에서 이름 OID가 안 먹음 | net-snmp가 MIB 파일을 로드하지 않음 | 숫자 OID만 사용. 벤더 OID는 함수 노드의 벤더별 맵으로 관리 |
| SNMP 배치 일부 실패로 전체 미전송 | 응답 실패가 잦음 | batch join 타임아웃 20초, 일부 실패해도 나머지 전송 |
| 느린 장비(IE2000 등) 타임아웃 | `-t 2 -r 1`이 짧음 | `-t 5 -r 2`, exec 타임아웃 40초 |
| GETBULK에 응답 안 하는 장비 | 장비별 GETBULK 미지원 가능성 | 해당 장비만 `snmpwalk`(GETNEXT)로 처리 |
| fping 디스커버리가 안 됨 | non-root raw socket 권한 없음 | `sudo setcap cap_net_raw+ep $(which fping)` |
| 디스커버리가 중복 등록 시도 | 구 디스커버리와 discovery2가 동시에 동작 | 구버전 탭 Disable |
| Modbus 값이 엉뚱함 | `node-red-contrib-modbus` 서버 노드는 값을 바이트 단위로 기록(`bufferFactor=8`), 읽기는 16비트 레지스터 | 16비트 값을 빅엔디안 2바이트로 나눠 기록 |

## 4. 토폴로지

| 증상 | 원인 | 해결 |
|---|---|---|
| 링크에 포트 번호가 안 보임 | 백엔드는 엣지 라벨(`"Gi0/1→eth0"`) 제공, 프론트 엣지 스타일에 `label` 없음 | `Topology.jsx` edge 스타일에 `label: "data(label)"` 추가 (미착수) |
| WebSocket 갱신 때 LLDP 링크와 세그먼트가 사라짐 | WS 스냅샷에 링크/세그먼트가 없어 덮어씀 | `/api/topology`를 10초마다 다시 조회하도록 수정 (2026-06-07) |
| LLDP 이웃이 매칭 안 됨 | 스캐폴드가 sysName으로 매칭, 디스커버리 장비 이름은 `disc-<IP>` | 이웃 관리 IP(`lldpRemManAddr`)로 매칭하도록 실스위치 출력 보고 확정 |
| CDP 링크 주소/포트가 부정확 | `cdpCacheAddress` hex→IP 디코딩 형식, `local_port`가 ifIndex 숫자 | 실스위치 walk로 디코딩 확정, ifName walk 추가 |

## 5. 인증 켤 때 주의 (코드 점검으로 발견, 미검증)

- `AUTH_ENABLED=true`로 켜면 수집 토큰 경로 5개를 뺀 나머지는 로그인 토큰이 필요합니다.
- 그런데 Node-RED 플로우는 다음을 호출합니다.
  1. `GET /api/devices` (ping, SNMP, 인터페이스, CDP 플로우가 대상 목록 조회)
  2. `GET /api/discovery`, `PUT /api/discovery` (discovery2 플로우)
  3. `PATCH /api/devices/{id}` (식별 플로우)
  4. `POST /api/fdb`, `POST /api/assets` (향후 수집 플로우)
- 그대로 켜면 이 호출들이 401로 막혀 수집이 멈출 가능성이 큽니다.
- 켜기 전 할 일: 위 경로를 수집 토큰 검사 대상에 포함하거나, Node-RED용 계정 토큰을 발급해서 헤더로 넣는 방식 중 하나를 정해 코드 수정

## 6. 개발 방식에서 얻은 원칙

- 신규 기능은 `.env` 토글 기본 OFF로 넣어서 배포만으로는 기존 동작이 바뀌지 않게 함
- 추가 패키지 없이 표준 라이브러리 우선 (VM에서 pip 단계 제거)
- 코드 전달 전 검증: 프론트 esbuild 문법 검사, 백엔드 `python3 -m py_compile`, Node-RED 플로우 JSON 파싱
- 문서보다 저장소 코드가 앞서 있을 수 있음. 작업 전 저장소를 받아 실제 상태 확인
- 실장비나 VM이 필요한 작업은 기록해 두고 VM 세션 때 처리
