## 2. 바로 할 일 (VM 필요)

### 2.1 Node-RED 플로우 저장소 백업 (최우선)

플로우가 VM에만 있어서 VM이 망가지면 수집기를 전부 다시 만들어야 합니다.

```bash
# (VM) 1. flows.json만 복사 (자격증명 파일 제외)
cd ~/KSdev_NMS && mkdir -p nodered
FLOW=$(ls ~/.node-red/flows.json 2>/dev/null || ls ~/.node-red/flows_*.json 2>/dev/null | grep -v cred | head -1)
echo "발견된 플로우 파일: $FLOW"
cp "$FLOW" nodered/flows.json
ls -la nodered/

# (VM) 2. 민감정보 점검 (public 저장소)
grep -inE "password|secret|token|apikey|community|webhook" nodered/flows.json

# (VM) 3. 자격증명 파일 커밋 차단
grep -q "_cred" .gitignore || printf '\n# Node-RED credentials\nnodered/*_cred.json\n' >> .gitignore
tail -3 .gitignore
```

- 2번에서 `community: "public"` 외의 실제 비밀번호나 토큰이 보이면 올리기 전에 값을 지우거나 환경변수로 빼야 합니다
- 반영 방법은 둘 중 하나
  1. VM 파일을 PC로 옮겨 GitHub Desktop으로 커밋
  2. VM에서 직접 `git push` (GitHub 토큰 인증은 본인이 직접 설정)

### 2.2 인터페이스 자동 수집 마무리

1. Node-RED에서 기존 "NetVision Interfaces" 탭 삭제
2. 최종본 `netvision_interfaces_flow.json`(ifTable 단일 walk) Import → Deploy
3. 30초 뒤 `02` 11절의 인터페이스 현황 명령 실행 → 239, 240, 241이 `ports>0`이면 정상

## 4. 실장비가 있어야 확정되는 작업

| 작업 | 필요한 것 |
|---|---|
| SNMP CPU OID | 모델별 `snmpwalk` 결과 (Cisco 예: `1.3.6.1.4.1.9.9.109.1.1.1.1.7`, 모델별 확인 필요) |
| LLDP 파싱/매칭 | `lldpRemSysName`(`1.0.8802.1.1.2.1.4.1.1.9`), 관리 IP(`1.0.8802.1.1.2.1.4.2.1`) 출력 |

| 링 모니터링 (MRP, PRP, REP) | 장비별 상태 OID 또는 CLI |
| Config 백업 | SSH 접근 정보, 대상 장비 |

| 미관리 세그먼트 실검증 | Managed SW + Unmanaged SW + 단말 여러 대 구성 |
